# Sony Device Center 2.0.5 验收记录

开始日期：2026-11-01，更新日期：2026-11-02，Asia/Shanghai。状态：自动化回归、两小时长测与本地开发包核验通过，真机及全新 Windows 环境待验收。
先前在默认渲染问题发现前生成的包已经移入构建审计目录，不作为交付包。
本轮重新生成的 2.0.5 本地未签名开发包用于继续验收，不标记为最终真机验收通过版。

## 已实现的连接规则

- 软件主动断开、Windows 断开和原因不明的断开均保存按地址区分的暂停记录；重启软件也不自动打开该设备的控制通道。
- 手动连接只清除所选设备的暂停。暂停时继续观察 Windows 状态，耳机自行连电脑后显示“系统已连接，软件控制已暂停”，不阻断或回切音源。
- 软件关机另存等待开机标记，保留五秒静默期；Windows 肯定报告同一耳机已连接后才恢复控制。未连接、未知和枚举失败均不授权自动连接。
- 系统链路保持连接、控制通道半开时，允许按现有退避恢复同一目标，保留通话切回恢复能力。正常退出仅释放资源，不误写主动暂停。
- 当前电脑的多点断开进入暂停；其他设备的多点断开不误暂停当前会话。新策略由 Windows GUI 明确启用，其他平台和 daemon/CLI 保留原策略。

## 状态与执行

同设备、同会话的确认值在暂时读取失败时保留，并显示更新延迟与电量时间。
暂停或真实断连不把历史电量显示为实时值。快照携带会话、版本及选择代数，拒绝旧设备、旧会话及乱序快照。

后台协调和串行 I/O 使用持续存在的 Qt 线程，通知直接发布不可变快照。
取消、退出可中断 Windows socket 等待与协议忙碌重试。待执行队列上限 32，离散操作保序，
连续且尚未发送的滑块输入合并并保留最终值，满载明确反馈。普通设置进行定向读回确认，关机保留专门流程。

真实设备会话不再缓存未匹配回复用于确认后续请求。新增回归模拟“旧查询回复先到、新设置被设备忽略”：
修复前两条断言失败，修复后三条断言通过。通知仍立即分发；协议没有通用事务标识，
因此无法承诺识别所有恰在同操作码请求等待期间到达的延迟帧。

在独立部署测试中，初版一次性 std::async 线程退出曾触发 Qt 线程本地数据清理的访问冲突；
调用栈与基线对照后改为持续 Qt I/O 线程。修复后软件渲染、默认渲染和 OpenGL 均通过同一页面/托盘测试。

## 资源对照与边界

- 相同 XM6 模拟传输、默认渲染、托盘运行与每分钟重连，取 30–115 秒样本：基线平均私有内存 128.33 MiB，新版 113.65 MiB；这不是实际耳机长期内存结论。
- 裁剪六组未使用的非 Basic 样式后，独立载荷约 140.51 MiB；原始基线约 162.42 MiB，少约 21.91 MiB。保留原图、Basic、Templates、平台插件、图形回退及编译器运行库。66 个保留 DLL 未引用被裁掉的样式 DLL。
- 图片按显示大小、DPI 与悬停比例限制解码，隐藏窗口/页面停止循环动画，窗口与页面保留，托盘图标仅在电量/连接/充电变化时重绘。
- 相同模拟传输、单次持续连接的一小时调度：维护查询 760 → 681 次；固件查询 80 → 1 次，电量查询仍为 120 次，其他设置查询均保持原频率。有效通知重置约 30 秒电量兜底期限，隐藏窗口不延长设置约 45 秒轮询兜底。每分钟重连的资源长测会在新会话初始化时额外读取电量，不直接比较两种场景的请求总数。
- 单通道正在等待回复时不能抢占已有请求，故退化链路不承诺严格每 30 秒完成。耳机实际续航未做长时间重复对照，不给出省电百分比。
