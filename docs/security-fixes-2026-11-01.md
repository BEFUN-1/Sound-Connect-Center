## P0-1：安装器权限与路径

采用固定目录的当前用户安装模型：

- NSIS 使用 `RequestExecutionLevel user`，安装及卸载初始化检查 TokenElevation，拒绝继承高权限 token。
- 只允许 `%LOCALAPPDATA%\Programs\Sony Device Center`，不再读取 HKCU InstallDir，也不提供目录选择页。
- 拒绝自定义 `/D`、路径解析失败、安装树及祖先路径中的 reparse point。
- 移除对旧目录内 EXE 的 `ExecWait` 和按名称执行的全会话 `taskkill`。
- 移除递归 runtime 清理；卸载只删除生成清单中列出的文件，未知文件保留。
- 结束页的启动应用复选框默认不选中。更新前应从托盘退出应用。

路径校验初次运行测试暴露了路径解析返回空值后继续遍历的问题。
最终实现使用 Win32 路径规范化、检查返回值并在失败时立即退出；
父目录遍历在到达根部时停止。编译后的测试既检查允许路径能通过，
也检查自定义目录和目录联接会被拒绝，避免“所有路径都拒绝”的假通过。

Windows Authenticode 已接入正式打包：先签署三个项目 EXE，再签署安装器，
每次随后验签并要求时间戳。证书未配置时正式打包失败；`-Development`
仅生成名称含 `-dev` 的开发包。此环境未提供证书，没有执行真实签名。

## P0-2：自动连接目标

最小复现命令：

```powershell
build-win-tests2/tests/sony-core-tests.exe "[selection]"
```

修复前新增的两个测试共 9 个断言，6 个失败：空地址会连接第一台耳机，
目标变化后关机请求仍能发给旧设备。复现只使用模拟蓝牙传输。

最终行为：

- 自动连接接口必须显式传地址；空地址关闭自动连接，非法地址拒绝。
- 只重试所选地址，不会在目标缺失或连接失败时尝试另一台候选设备。
- 改变目标立即关闭旧控制会话。
- GUI 首次使用等待手动选择；接受选择后保存地址，首次连接失败及后台恢复仍保留新目标，重启时不会恢复更早选择的设备。
- 损坏的已保存地址被清除，设备列表与手动选择仍可用。
- `sonyd` 未带 `--device` 时保持空闲；模拟模式使用明确的虚拟地址。
- 写命令验证所选地址与活动目标；GUI 队列请求附带 `targetAddress`，拒绝旧设备请求。
- 发现过滤要求合法地址和耳机型号名；OUI 表不作为连接授权依据。

Qt 测试使用显式的默认格式设置存储，测试环境重定向到临时 INI，
正常应用仍默认使用平台原生设置。测试不会改写真实用户的设备选择。
